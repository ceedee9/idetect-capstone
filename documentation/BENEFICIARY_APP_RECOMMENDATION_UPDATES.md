# Beneficiary App Recommendation Updates

**Updated:** October 4, 2026

## Implemented

- Added an **Other** dispute category in the beneficiary app, with English and Filipino labels. The API accepts and stores it as its own dispute type; the existing four categories remain unchanged.
- Expanded the **History** tab into a chronological, paginated timeline combining verification transactions with beneficiary-submitted disputes and reports. Entries show localized statuses and dates/times.
- Improved English/Filipino consistency for beneficiary and dispute statuses and displayed dates.
- Replaced the switch-to language label with an **EN / FIL** selector that highlights the currently applied language; accessibility labels and tooltips use the full language names.
- Replaced the repeated beneficiary name/type in the app header with **iDetect / Beneficiary Portal**.
- Redesigned the Status tab identity card with a high-contrast status chip, an integrated beneficiary-type descriptor, and a labeled ID number masked by default with a show/hide control.
- Added clear unavailable and retry states for failed History, Disputes, and Notifications loads instead of showing a misleading empty list.
- Corrected the beneficiary widget smoke test setup to provide its locale dependency and explicitly import Flutter Material widgets.

## Already Present

Verification notification messages already include the establishment name. No change was needed for that recommendation.

## Deferred

- Beneficiary photo/visual identification: excluded from this implementation by request.
- Red label: the matrix does not identify which label; clarify before changing it.
- Two-minute session timeout: left unchanged pending a decision on the timeout policy.
- Some notification titles and bodies are generated by the server and may still appear in English when the app is set to Filipino.

## Deployment and Validation

Migration `034_add_other_dispute_type.sql` is registered after the existing `033` migration. Apply the API migrations before submitting disputes with type `other`; the database migration was not run as part of this app change.

The beneficiary widget test completed successfully (1 passed, 0 failed), and the beneficiary project analyzer reported no errors.
